# K-Coupon Japan — 기능별 상태 분류 (2026-10-28)

각 기능을 아래 상태 중 하나로 분류했습니다. **"PASS"는 코드와 자동 테스트, 또는 운영 사이트에서 직접 확인한 것에만** 붙였고, 실제 계정·실제 휴대폰·외부 콘솔이 있어야 확인되는 것은 PASS로 두지 않았습니다.

| 상태 | 뜻 |
|---|---|
| `PASS` | 구현과 검증이 끝남 (근거를 같이 적음) |
| `CODE_FIX_REQUIRED` | 코드 수정이 더 필요함 |
| `CONFIG_REQUIRED` | 외부 서비스(Supabase·Resend·DNS·Vercel 등) 설정이 필요함 |
| `DATA_REQUIRED` | 실제 데이터(매장·쿠폰)가 필요함 |
| `BUSINESS_REQUIRED` | 사업자·제휴·정책 결정이 필요함 |
| `TEST_REQUIRED` | 실제 환경(실계정·실기기·대시보드)에서 검증해야 함 |
| `BLOCKED` | 권한 또는 필수 정보가 없어 진행할 수 없음 |

검증 근거 약칭: **단위** = `npm test`(45개), **DB** = 로컬 PostgreSQL 시험(81개), **점검** = `npm run smoke`(운영 사이트 71개), **운영확인** = 운영 사이트·운영 DB에서 직접 읽어 확인.

| 계정 삭제 | PASS(코드) / TEST_REQUIRED | 연관 데이터·사진 삭제를 코드로 확인. 실제 삭제 실행은 하지 않음 |

## 쿠폰 발급·사용

| 기능 | 상태 | 근거 / 남은 것 |
|---|---|---|
| 쿠폰 발급(공개·활성·기간·중복·한도) | PASS | DB 시험(동시 40명→정확히 10장 등), 단위(안전장치), **운영확인: `issue_coupon` 설치·서버만 호출 가능** |
| DB 함수 없을 때 수량 제한 쿠폰 차단 | PASS | 단위(변이 테스트로 검증) |
| QR/코드 식별·검증 | PASS(코드) / TEST_REQUIRED | QR에는 발급 이벤트 ID만 있고 개인정보 없음. 실기기 스캔은 미확인 |
| 사용 처리: 관리자만, 만료·중지·중복 거부, 동시 1회 | PASS | DB 유니크 인덱스(시험), 코드. 운영 실행은 미시험 |
| 처리자 기록(`redeemed_by`) | CONFIG_REQUIRED | 코드·마이그레이션·한 번짜리 적용 파일 완료(DB 시험 포함). **운영 DB에는 아직 적용 전** — 적용 전에도 사용 처리는 정상(Sentry 경고만) |
| 매장 직원 전용 계정·화면 | CONFIG_REQUIRED | 코드·마이그레이션·한 번짜리 적용 파일·관리 화면(`/admin/staff`)·직원 화면(`/staff/redeem`) 구현 완료, 권한 규칙 단위 시험 + DB 시험(11번) 통과. **운영 DB에는 아직 적용 전**(`apply-store-staff.sql`) — 적용 전·연결 전에는 아무에게도 권한이 없고 기본은 "운영자 대리 처리". 실제 직원 계정 종단 시험은 본인 테스트 계정 2개로 켠 직후 수행(런북 1번 B안 7항) |
| 포인트 적립 | PASS | 시험(중복 적립 방지). 사용 기능은 의도적으로 비활성(`BUSINESS_REQUIRED`: 사용처 정책) |

## 관리·보안·운영

| 기능 | 상태 | 근거 / 남은 것 |
|---|---|---|
| 관리자 매장·쿠폰·공지·랜딩 관리, 공개 전 검수 | PASS | 새 쿠폰·매장은 항상 비공개로 저장되고 편집에서 공개(런북 9번) |
| 관리자 접근 제어(서버 검증, RSC 유출 없음) | PASS | 점검(운영): 비로그인 경로 11개 차단, RSC 12요청 유출 0 |
| DB 접근 규칙(RLS) | PASS(동작) | 운영확인: 14개 테이블 익명 0건. 정책 목록을 대시보드에서 전수 열람하지는 않음 |
| 보안 헤더·오픈 리다이렉트·이미지 SSRF | PASS | 점검(운영) |
| 의존성 취약점 | PASS | 운영 의존성 0건(Next 16.4.3, zod 4.6.7). 개발 도구 5건은 패치가 아직 없어 보류(배포물 미포함) |
| 비밀값 노출 | PASS | 저장소·이력에 없음 확인 |
| 오류 모니터링(Sentry) | TEST_REQUIRED | 코드 연결. **대시보드에서 수신 확인 필요**(시험 절차: 런북 D) |
| 크론 | PASS(인증·점검모드) / TEST_REQUIRED | 인증·dryRun 운영확인. 정기 실행은 로그상 추정 |
| LINE 알림 실수신 | TEST_REQUIRED | 코드 완료, 실제 수신 미확인 |
| 롤백·장애 대응 | PASS | 런북 12번(발급 중단, 이전 배포 되돌리기) |
| DB 백업·복구 | BLOCKED | Supabase 대시보드 확인이 필요(제가 접근 불가). 기본 스키마가 저장소에 없어 코드만으로는 복원 불가 |
| 실제 환경 검증(가입·메일·발급·사용) | TEST_REQUIRED | 격리 테스트 환경(별도 Supabase 프로젝트)이 없음 — 계획은 런북 10번 |
